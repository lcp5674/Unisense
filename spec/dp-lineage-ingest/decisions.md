# dp 调度血缘接入 — 已确认决策记录

> 状态：设计中（grill-me 会话）。每确认一条补充一条；落地前整体 review。

## 背景
本地 dp 数据源（id=4, mysql）`dp_stable` 是数开/调度平台元数据库（107 表）。
- `dispatch_task`（65 列，~1390 个非删除任务）：任务主表，`out_table`=最终产出（如 `wedw_dwd.dp_dq_measure_df`），type=1 占 1299（SQL 任务）
- `dispatch_task_step`（20 列，**节点表**）：task_id 关联，`script_info` 存节点内容——stype=7 Hive/Spark SQL（1596 条）、stype=2 DataX JSON（628 条）、其余 shell/质量
- 一个任务 2~8 个节点；SQL 形态：set/use 前缀 + drop + 纯建表 DDL（无数据流）或 CTAS/INSERT SELECT（真实数据流转）

## 已确认决策

### D1. 主体粒度：节点级（方案 A）
每个 `dispatch_task_step` 的 SQL 独立解析，还原真实加工链路（含中间表）。
任务/节点不作为血缘图实体；任务信息作为边的 provenance 元数据。

### D2. 字段级：A+B 全链路字段级
- 每个节点的 CTAS/INSERT SELECT 都解析「本节点目标表每列 ← 上游源列」
- 中间表既作上游目标又作下游源，串成完整字段级链路
- 聚合/计算列（count/sum/concat）无直接字段来源 → 落到表级，标「表达式列」，不造假映射
- **字段映射独立成表**（每行一个源列→目标列，可单独查询/审计/按字段回溯），不是边的附属 JSON

### D3. 任务动态属性：静态落边 + 动态旁路
- 血缘边只承载不变任务身份：task_id / task_name / 负责人 / 项目 / 产出表
- 动态属性（任务状态 / 最近执行时间）不走存储层，展示时实时拉取 dp 库旁路展示
- 组合体验：点开边详情 = 静态信息 + 实时状态 + 最近执行

### D4. 写入语义（四层）
1. 同任务多节点产同一表 → 表级输入聚合（Y←{X,Z} 一条边），字段映射聚合
2. 跨任务产同一表 → 合并同一条边，provenance 为集合（多条 task#step）
3. 与既有血缘同源同目标 → 复用/增强现有边（补 provenance + 字段映射），不建并行重复边
4. 全链路幂等：重复解析不产生重复边/重复字段映射
- 审计：原始构成快照（raw）与血缘权威视图分离，审计日志另存

### D5. LLM 定位：sqlglot 主 + LLM 共识确认
- **主链路**：sqlglot 确定性解析（L1 表级 + L2 字段级）
- **共识确认**：sqlglot 结果交 LLM 确认——
  - 一致 → 判定成功直接入库（confidence=high / source=sqlglot+llm）
  - 不一致 → 把 sqlglot 结果 + 原始 SQL 交 LLM 仲裁判断；分歧记录为**待人工抉择**（不静默入库）
- **兜底**：sqlglot 失败的 L3/L4 → LLM 提炼数据流转，标 confidence=low / source=llm，仅作参考边，进人工抉择工作台
- **语义增强**：LLM 给中间表/字段补业务语义 description（锦上添花）
- **前端可视化操作**：确认/兜底/分歧结果均可前端人工抉择

### D6. 分级确认（方案 B，成本边界）
- 简单节点（sqlglot 干净解析且无 L3 特征）→ **跳过 LLM 确认**，直接入库（high / sqlglot）
- 复杂节点（多层子查询/CTE/窗口/多 join/方言特征/解析告警）→ **走 LLM 确认**（一致入库、不一致仲裁）
- 解析失败节点（L3/L4）→ **LLM 兜底**（low / llm），进人工抉择
- 复杂度分级规则可前端配置（预计 LLM 调用量砍到全量 20~40%）

### D7. 生产实时更新：定时增量轮询（方案 A）
- 后台周期任务扫描 dp 任务/节点变更（按 update_time 水位增量），自动入队增量解析写血缘
- 新鲜度 = 轮询间隔，**间隔前端可配置**（默认 5 分钟，可调 1~1440 分钟）
- 增量/幂等/provenance 保证重复安全

### D8. 前端可视化配置范围与落点（Q8）
- **落点：方案 A**——血缘模块内新增「血缘同步/接入」页（与血缘图谱/健康度并列），配置 + 人工抉择工作台同域（可同页不同 Tab）
- **配置项范围（该进配置页）**：① 同步总开关；② dp 源/库/任务表·节点表；③ 轮询间隔（1~1440 分钟）；④ 任务/节点类型过滤；⑤ 排除规则（任务/目标表前缀）；⑥ LLM 复杂度分级规则；⑦ LLM 模型/开关（可关 LLM 走纯 sqlglot）
- **运维动作（不放配置主区）**：解析运行记录（每轮扫描成功/失败/分歧数）+ 增量水位查看/手动重置（触发全量）——单独运维区/并入血缘健康度审计
- **权限**：配置/运维/抉择操作需血缘管理权限（dp 同步是数据写入，须权限收敛）

### D9. 人工抉择工作台（Q9）
- **对象粒度**：一个节点（step）一次解析 = 一张待抉择单（含原始 SQL、sqlglot 结果、LLM 仲裁意见、分歧原因），单内展示该节点的全部候选边/字段映射——审「节点解析对不对」，不逐条边审
- **操作选项**：采纳 sqlglot / 采纳 LLM / 手动修正（直接改边或字段映射）/ 忽略此节点（不写血缘，标已处理）
- **留痕**：谁、何时、采纳谁、有无手动改
- **记忆闭环**：已裁决节点 + SQL 内容指纹（hash）未变 → 自动复用上次裁决结果，不再进待抉择；SQL 变了才重新裁决
- **无法解析**：sqlglot 与 LLM 都失败且 LLM 提炼不出流转 → 标「无法解析」，**展示该节点内容供用户手动配置**（不无限重试，运行记录可见）

### D10. 任务/节点元数据承载 + 资产 Owner 回填（Q10）
- **元数据承载（方案 A：静态落边快照 + 增量顺刷）**：责任人链（director/created_user_id/modified_user_id/checker/settle_project_director）、组织归属（project/menu/settle_department/budget_unit）、调度配置（cycle/cron/week_day/month_day/specific_time/frequence）、描述（remark/task_version_desc/task_version）、主从（master_task_id/is_master_task）、节点级（task_step_name/task_node_type/task_step）→ **落 `dp_task_refs` 做快照**；任务 id 不变但上述字段变更 → 增量解析**顺手刷新**该任务所有边的 dp_task_refs（边本身不动）
- **动态运行态（状态/最近执行）**：不落边，展示层实时旁路拉 dp 库（与 D3 一致）
- **资产 Owner 回填（防孤儿）**：dp 产出表已资产化（实测 115 张 `wedw_dwd.dp_*` 在资产目录），解析后对产出表资产实体：
  - **仅在资产 owner 为空（孤儿）时回填**——已被人工认领/治理的资产**绝不覆盖**（血缘同步无权限覆盖人工决策）；可配置策略 = 仅孤儿回填（默认）/ 不回填
  - director → 平台用户匹配：**优先匹配 `user.username`**；匹配不到 → **自动创建影子用户**（username=dp 账号、display_name 初始占位、status=disabled 不可登录、归属「外部协作」组织）再挂 owner_id；管理员后期在平台用户管理配置真实中文用户名
  - **不做独立 dp_user_mapping 中英文映射表**（Q10c 收敛：同 Q10a 走平台用户体系）
  - 回填留痕（谁触发/影子用户创建记录），资产地图按现有逻辑展示（owner 非空即不进孤儿列表）

## 收尾默认值（Q9 后确认，无异议默认采纳）
1. **入图规则**：真实表全量入图，但过滤明显临时表（`tmp/temp/_bak/adhoc` 前缀或 dp 内部规则，可配置）——避免图谱噪音
2. **删除语义**：任务/节点删除 → 血缘边标 **deprecated 保留历史**（血缘是历史事实），不物理删边
3. **轮询载体**：复用现有 **arq worker**（新增周期任务，同队列、同内存锁/健康检查机制）
