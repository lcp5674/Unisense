## 1. 引言

### 1.1 项目背景

公司已建设一套基于 **YAML 数据文件 + 静态 HTML 页面 + Flask 服务**的指标语义平台原型，覆盖指标三层（原子/派生/复合）定义、数据集语义、业务术语/词根、语义血缘、统一查询、生命周期等能力，并配套 `metric-mapping`（需求指标映射）与 `metric-creator`（指标录入）两个 Codex skill。

该原型**即本次产品化的需求基线**：页面交互、数据字段、接口行为均已可运行、可演示。本次开发目标为：

1. 将原型从"YAML 文件存储 + 全量加载"升级为**生产级存储与检索**，支撑 10 万张表、四位数指标、上百数据集的规模；
2. 补齐平台对外 REST API（含批量/幂等/分页能力），支撑前端页面与智能体 skill 稳定消费；
3. 保留原型全部功能与交互，修复已知不一致（如页面字号规范、导航一致性、挂载表 schema 映射漂移）。

### 1.3 术语表

| 术语 | 定义 |
|---|---|
| 原子指标 | 统计口径 + 算法抽象，不绑定业务场景和物理表 |
| 派生指标 | 依赖指标（原子或派生）+ 业务限定 + 统计周期 + 指标类型，不加统计粒度 |
| 复合指标 | 多个派生指标的公式组合（比率/占比/差值） |
| 数据集 | 指标挂载的物理表语义层，英文名 = 表名，决定统计粒度 |
| 挂载表 Schema | 表字段与指标映射的结构化描述 |
| 词根 | 英文命名的最小语义单元（中文词根 ↔ 英文词根映射） |
| 统一查询 | 指标/数据集语义检索入口（中文名/同义词/描述分词模糊匹配） |
| 语义血缘 | 指标/数据集的上游（来源表/依赖指标）与下游（派生/挂载表）DAG |
| skill | Codex 技能：metric-mapping（映射）、metric-creator（录入） |

## 2. 总体架构

### 2.1 现状架构（需求基线）

```text
┌─────────────┐   HTTP    ┌──────────────────┐   读/写    ┌────────────┐
│ 静态 HTML    │ ────────▶ │ Flask metrics_    │ ────────▶ │ YAML 文件   │
│ 页面(12个)   │ ◀──────── │ server.py          │ ◀──────── │ index/*.yaml│
└─────────────┘           └──────────────────┘            └────────────┘
        ▲                          │
        │ REST                     │ REST
        │                          ▼
┌─────────────┐           ┌──────────────────┐
│ skill       │           │ 统一查询/血缘/     │
│ metric-*    │           │ 批量接口(待补齐)   │
└─────────────┘           └──────────────────┘
```

### 2.2 生产目标架构

```text
┌─────────────┐   HTTP    ┌──────────────────┐   SQL    ┌──────────────┐
│ 前端(静态+JS)│ ────────▶ │ API 服务(生产)     │ ───────▶ │ MySQL/PG      │
│             │ ◀──────── │ (分页/批量/幂等)    │ ◀─────── │ + ES/倒排索引  │
└─────────────┘           └──────────────────┘          └──────────────┘
        ▲                          │
        │ REST                     │ 定时/事件
        │                          ▼
┌─────────────┐           ┌──────────────────┐
│ skill       │           │ 数据源表元数据同步  │
│ metric-*    │           │ (10万表 增量拉取)   │
└─────────────┘           └──────────────────┘
```

### 2.3 架构决策

| 决策 | 说明 | 理由 |
|---|---|---|
| D1 存储迁移 | YAML → 关系型数据库（MySQL/PG）+ 检索索引（ES 或 MySQL FULLTEXT） | 10 万表 schema 全量加载内存不可行；指标检索需索引化保证 P95 < 300ms |
| D2 表元数据分表 | 表/字段独立表，按表名前缀索引 | 10 万表分页查询 |
| D3 批量接口 | batch-validate / batch-draft 服务端批处理，≤100 条/次 | 支撑指标录入高频场景 |
| D4 幂等写接口 | datasets/register、metrics/draft 按唯一键幂等 | 防止 skill 重复提交 |
| D5 前端兼容 | 前端仍为静态 HTML+JS，通过 REST 消费；build_static.py 保留供演示 | 减少前端重写成本 |
| D6 YAML 兼容导出 | 保留 YAML 导出能力（接口或后台任务） | 满足离线备份/评审需求 |

### 3.1 module-01 首页与统一查询

| FR | 需求 | 验收要点 | 状态 |
|---|---|---|---|
| FR-01-01 | 首页资产统计大盘：8 类资产卡片（主题域/原子/派生/复合/挂载表/数据集/术语/词根） | 统计数与数据库一致；生产环境 < 1s | 已实现 |
| FR-01-02 | 统一查询：输入单个或多个指标/数据集关键词，返回推荐结果按相关性降序 | 指标匹配 中文名+同义词；数据集匹配 名称（=表名）/中文名/描述；分词模糊 | 已实现 |
| FR-01-03 | 统一查询支持数据集查询 | 返回推荐数据集，相关性第一 | 已实现 |
| FR-01-04 | 查询结果点击跳转详情/血缘 | 指标→详情页；数据集→数据集详情 | 已实现 |
| FR-01-05 | 生产检索性能 | P95 < 300ms；分页返回 | 待开发 |

**统一查询算法说明**（FR-01-02/03 实现基准）：

1. 匹配字段：指标 = 中文名称 + 同义词；数据集 = 数据集名称（=表名）+ 中文名称 + 一句话描述。
2. 分词：输入按 `空格/，/,/、/和/与/及/;/；/换行` 切分；对每段做**词典最长匹配**（词典=全量中文名+同义词，按长度降序）。
3. 模糊：未完整命中时取与词典词**公共前缀 ≥ 2 字符**作为分词（如"发生了"→"发生"）；连续单字丢弃。
4. 匹配类型 `matchedBy` 枚举：`中文名称-前缀` / `中文名称-包含` / `中文名称-近似` / `同义词` / `数据集名称` / `描述`。
5. 相关性：匹配类型权重 + 命中长度 + 词典词长度综合打分，按 `score` 降序；分数相同按指标类型（原子→派生→复合）与序列号稳定排序。

| FR-05-05 | 支持按指标查询、按数据集查询血缘 | 默认按当前指标查询 | 已实现 |

**血缘接口数据结构**（FR-05-01~05 实现基准，`POST /api/semantic/lineage`）：

```json
{
  "nodes": [{"id": "root", "type": "root", "label": "结余率", "sub": "复合", "level": 0}],
  "edges": [{"from": "metric:69", "to": "root", "label": "依赖"}]
}
```

- `level`：负=上游、0=根、正=下游；默认 `depth=1` 只取一层；
- 根节点规则：原子根 → 上游=来源主表（`table:<表名>`）、下游=派生指标（`metric:<序列号>`）；派生根 → 上游=依赖指标、下游=挂载数据集（`dataset:<表名>`）；数据集根 → 上游=上游表、下游=挂载指标；
- 同一条边只输出一次（按 `from||to` 去重）。

## 4. 数据模型

### 4.1 生产存储设计原则

1. 实体关系与现有 YAML 字段一一对应，**字段名保持中文键**（数据库列可映射英文），避免口径漂移；
2. 表/字段元数据单独分表存储（10 万表规模），不与其他实体混存；
3. 状态、负责人、术语标签、挂载关系使用关联表/多值表；
4. 保留 YAML 导出能力作为离线快照。

### 4.2 核心表设计建议

| 表 | 说明 | 关键字段 |
|---|---|---|
| `domain` | 主题域 | 编号(DOM-xxx 唯一)、名称、描述、核心业务对象 |
| `metric` | 指标主表 | 类型(atom/derived/composite)、序列号、英文名称(唯一)、中文名称、数据域、度量格式/单位/小数位、状态、负责人 |
| `metric_atom` | 原子指标扩展 | 来源数据源/来源表、聚合函数、计算逻辑(标准/自定义)、累加类型、过滤条件、时间字段、技术口径 |
| `metric_derived` | 派生指标扩展 | 依赖指标(可多值)、指标类型、业务限定、限定口径、支持统计周期、计算逻辑、时间字段、挂载数据集 |
| `metric_composite` | 复合指标扩展 | 公式、依赖派生指标 |
| `metric_synonym` | 同义词多值表 | 指标 id、同义词 |
| `metric_tag` | 术语标签关联表 | 指标 id、术语 id |
| `dataset` | 数据集 | 数据集名称(=表名 唯一)、数据源、中文名称、分层、更新周期、粒度、描述、QBI 数据集 id |
| `dataset_metric` | 数据集-指标挂载 | 数据集 id、指标 id、字段名 |
| `table_meta` / `column_meta` | 表/字段元数据 | 表名(库名.表名 唯一)、字段名、类型、注释、关联指标；按表名前缀建索引 |
| `term` / `term_type` | 业务术语 / 术语类型 | 术语名称、英文名称、类型多值、定义、同义词、关联词根/指标 |
| `glossary_root` | 词根 | 中文词根、英文映射、缩写、说明、状态(待审核/已注册)；同一英文映射唯一 |
| `datasource` | 数据源 | 类型(Doris/Hive)、连接信息、状态 |
| `metric_status_log` | 状态流转日志 | 指标 id、from/to 状态、操作人、时间 |
| `dataset_metric` | 数据集-指标挂载关联 | 数据集 id、指标 id、字段名、挂载人、挂载时间；唯一约束(数据集 id, 指标 id) |

**索引与血缘支撑**：

- `metric.英文名称` 唯一索引（原子/派生/复合共享命名空间）；
- `table_meta.表名`、`column_meta(表 id, 字段名)` 唯一索引；`table_meta.表名` 前缀索引支撑 10 万表分页模糊查询；
- `dataset_metric(数据集 id)`、`metric_derived.依赖指标`、`metric_atom.来源主表` 建立反向索引，血缘 DFS 按节点局部遍历（禁止全图扫描）；
- 检索字段（中文名称/同义词/描述）建倒排索引（ES 或 MySQL FULLTEXT）。

### 4.3 指标三层字段规格（录入/校验基准）

> **详细配置项表见 `docs/指标平台需求规格说明书_v2.0.md` 对应章节，本文档保留摘要与校验要点，不重复全文**：原子基础信息=5.3.1、口径与算法=5.3.2、取值与可累加性=5.3.3、状态与治理=5.3.4、物理参考信息=5.3.5、写作规范=5.3.6；派生=5.4.1~5.4.3；复合=5.5；数据集语义=5.6.1~5.6.2；挂载表 Schema=5.7。生产开发以 v2.0 详细表为准，v3.0 摘要仅作速查。

#### 原子指标

**基础信息（9 项）**：英文名称（`^[a-z][a-z0-9_]{2,63}$`，全局唯一，词根化去表化）、数据域（DOM 枚举）、中文名称、度量格式（金额/比率/数值）、度量单位（金额：分/元/万元/百万元/千万元/亿元/自定义，默认元；比率：小数/百分位数/千分位数/自定义，默认小数；数值：自定义，默认无）、小数位数（金额默认 2、比率默认 4）、源头系统（业务系统术语，多值）、同义词、指标描述（≤200 字，不承担口径定义；**存储键为"描述"，页面显示名"指标描述"**）。

**计算口径（9 项）**：来源数据源、来源表（默认 dw/dwd 明细层）、业务口径（口径定义，不含表名/物理字段名，四方评审必读；"指标口径"字段已废弃，以"业务口径"为准）、计算逻辑（标准：sum/max/min/count/count_distinct/avg/first_value/last_value；自定义：伪 SQL）、累加类型（可累加/半累加/不可累加，半累加必配不可累加维度）、过滤条件（仅数据有效性排除）、时间字段（first/last_value 或半累加时必填）、分析维度、技术口径(源业务库口径)。

**业务信息**：创建人/业务负责人/产品负责人/技术口径负责人/状态（新建/已发布/已修改/已下线）。

#### 派生指标

公共项：指标类型（筛选/累积计算/同环比计算/混合计算/转化计算）、依赖指标（本期支持原子，多选）、业务口径（保留在口径配置）、技术口径(源业务库口径)、挂载数据集（只读）。

类型专属项：

| 类型 | 附加配置 |
|---|---|
| 筛选型 | 业务限定、限定口径、支持统计周期、计算逻辑、时间字段 |
| 累积计算型 | 业务限定、时间周期类型、计算逻辑、时间字段 |
| 同环比计算型 | 计算逻辑（同比/环比增长率）、支持统计周期、时间字段 |
| 混合计算型 | 依赖指标（多选）、计算逻辑（A-B、A/B、自定义公式）、时间字段 |
| 转化计算型 | 初始事件指标、转化事件指标、链接字段、转化窗口、计算逻辑、时间字段 |

#### 复合指标

公式（仅引用派生指标英文名+四则运算/括号）、依赖派生指标（与公式引用一致）、描述。

**页面形态（与派生指标对齐，字段保持复合专属）**：独立详情页 `composite-detail.html`，基础信息=数据域/英文名称/中文名称/同义词/指标描述；计算口径配置=公式/依赖派生指标；业务信息=创建人/业务负责人/产品负责人/技术口径负责人/状态/术语标签。列表页含 状态/操作 列（查看详情/查看血缘/版本记录）。详细配置项表见 v2.0 5.5。

## 5. 接口需求

### 5.1 接口规范总则

1. 统一 JSON，UTF-8（`ensure_ascii=False`）；
2. 查询接口支持分页参数 `page/pageSize`（默认 1/20，上限 100）；
3. 批量写接口单次 ≤ 100 条；
4. 写接口幂等（按英文名/数据集名称唯一键）；
5. 错误返回 `{"status":"error","message":"..."}`，业务冲突返回 409；
6. 线上环境 API 与页面数据同源（同一数据库），禁止页面直读 YAML。

**错误码表**：

| HTTP | 场景 | 响应体 |
|---|---|---|
| 200 | 成功 | `{"status":"ok", ...业务字段}` |
| 400 | 参数缺失/非法（如 text 必填、type 枚举外） | `{"status":"error","message":"..."}` |
| 404 | 实体不存在（详情/血缘未找到节点） | `{"status":"error","message":"未找到节点"}` |
| 409 | 业务冲突（英文名已存在、被依赖禁止删除） | `{"status":"error","message":"英文名称已存在：xxx"}` |
| 500 | 服务端异常/实体加载失败 | `{"status":"error","message":"..."}` |

**分页响应统一结构**：

```json
{"status": "ok", "items": [...], "total": 123, "page": 1, "pageSize": 20}
```

**接口字段命名约定**：接口 JSON 字段与页面/数据文件一致，保持**中文键**（如 `英文名称`、`业务口径`、`挂载数据集`）；兼容英文键仅在入参兜底支持（如 `host` 等价 `主机`）。

### 5.2 已实现接口（保留）

#### 5.2.1 `POST /api/semantic/metrics` 指标检索

#### 5.2.2 `POST /api/semantic/datasets` 数据集检索

- 入参：`{"text":"药品费用","limit":10}`

- `type` ∈ atom/derived/composite；`id` = 序列号或英文名称
- 出参：`{"status":"ok","metric":{...全量口径字段...}}`（原子含 基础信息/计算口径/业务信息全部字段；派生含 指标类型/依赖指标/业务限定/限定口径/支持统计周期/计算逻辑/时间字段/挂载数据集/技术口径；复合含 公式/依赖派生指标/描述）

- 入参：`{"type":"atom|derived|composite|dataset","id":"...","depth":1}`

#### 5.2.5 `POST /api/metrics/validate` 单条查重

- 入参：`{"英文名称":"...","中文名称":"...","业务口径":"..."}`（英文名称必填）
- 出参：`{"status":"ok","english_unique":true,"conflict":null,"similar_metrics":[{"type":"派生","英文名称":"tnb_manage_cnt","中文名称":"糖尿病规范管理人数","reason":"中文名称相同"}]}`
- 判定规则：英文名精确冲突；中文名相同/业务口径或描述相同/同义词包含 → similar；错误：400（英文名称必填）。

#### 5.2.6 `POST /api/metrics/draft` 单条草稿

- 入参：`{"type":"atom|derived|composite","data":{...指标字段...}}`（data.英文名称必填）
- 出参：`{"status":"ok","message":"草稿已创建","序列号":169,"metric":{...}}`
- 规则：英文名唯一校验（重复 409）；序列号自动生成；状态默认"新建"；错误：400（type 非法/英文名缺失）、409（已存在）、500（加载失败）。

#### 5.2.8 `POST /api/datasources/test` 数据源连通性

- 入参：`{"主机":"...","端口":9030,"用户名":"...","密码":"...","库名":"..."}`（兼容英文键 host/port/user/password/database；主机与用户名必填）

### 5.3 生产必补接口（开发范围）

> 以下接口 schema 为本文档**定稿**，开发按此实现；字段保持中文键；批量接口单次 ≤ 100 条。

#### 5.3.1 `POST /api/metrics/batch-validate` 批量查重

- 入参：

```json
{"candidates":[{"英文名称":"tnb_manage_rate","中文名称":"糖尿病规范管理率","业务口径":"..."}, ...]}
```

- 出参：

```json
{"status":"ok","results":[
  {"index":0,"结论":"可新建","english_unique":true,"similar_metrics":[]},
  {"index":1,"结论":"已存在","conflict":{"type":"派生","英文名称":"tnb_manage_cnt","中文名称":"糖尿病规范管理人数"}},
  {"index":2,"结论":"相似","similar_metrics":[{"type":"复合","英文名称":"surplus_rate","中文名称":"结余率","reason":"口径定义相同"}]}]}
```

- 结论枚举：`已存在` / `相似` / `可新建`；错误：400（candidates 缺失或 >100 条）；性能：100 条 < 1s（NFR-04）。

#### 5.3.2 `POST /api/glossary/validate-names` 词根批量校验

- 入参：`{"names":["surplus_amt","medicine_settle_amt","gxy_manage_cnt"]}`
- 出参：

```json
{"status":"ok","results":[
  {"name":"surplus_amt","合法":true,"正则通过":true,"命中词根":["surplus","amt"],"缺失词根":[]},
  {"name":"medicine_settle_amt","合法":false,"正则通过":true,"命中词根":["settle_amt"],"缺失词根":["medicine"],"建议":"缺失词根需用户确认后注册"}]}
```

- 规则：按词根库贪心最长切分（下划线边界）；`缺失词根` 非空即 `合法=false`；错误：400（names 缺失或 >100）。

#### 5.3.3 `POST /api/metrics/batch-draft` 批量草稿

- 入参：`{"type":"derived","items":[{"英文名称":"...","中文名称":"...", ...指标字段}, ...]}`
- 出参：

```json
{"status":"ok","results":[
  {"index":0,"ok":true,"序列号":169,"metric":{...}},
  {"index":1,"ok":false,"message":"英文名称已存在：xxx"}]}
```

- 规则：逐条校验英文名唯一，**成功的写入，失败的返回原因不影响其余条目**；同一批次内英文名重复 → 后条返回失败；性能：100 条 < 3s（NFR-05）。

#### 5.3.4 `POST /api/glossary/draft` 词根新建草稿

- 入参：`{"中文词根":"药品","英文":"medicine","缩写":"","说明":"药品类型"}`（中文词根唯一）
- 出参：`{"status":"ok","message":"词根草稿已创建","状态":"待审核","词根":{...}}`
- 幂等：同一中文词根或英文映射已存在（含待审核）→ 返回 200 + 已存在标识 `{"status":"ok","已存在":true,"词根":{...}}`，不重复创建。

#### 5.3.5 `POST /api/datasets/register` 数据集注册

- 入参：

```json
{"数据集名称":"wedw_dws.settle_his_drug_doctor_month_stat_df","数据源":"hive","中文名称":"月度医师云药房+院内his费用统计表",
 "所属分层":"wedw_dws","更新周期":"T+1天","负责人":"wangyn3","粒度":"区域×医院×医师×药品×月份",
 "维度字典":[{"字段":"area_code","中文名":"区域编码"}],
 "度量字典":[{"字段":"total_amt","中文名":"总费用","单位":"元","口径":"sum(费用)","关联指标":"total_amt","指标类型":"派生指标"}],
 "上游表":["wedw_dw.settle_his_order_detail_df"],"下游表":[]}
```

- 出参：`{"status":"ok","message":"数据集已注册","数据集名称":"...","已存在":false}`
- 幂等：按 数据集名称（=表名）唯一；已存在返回 200 + `"已存在":true`，不覆盖已有记录；错误：400（数据集名称缺失/粒度格式非法）。

#### 5.3.6 `POST /api/datasets/<name>/mount` 数据集挂载指标

- 入参：`{"metrics":[{"字段":"total_amt","关联指标":"total_amt","指标类型":"派生指标"}, ...]}`
- 出参：`{"status":"ok","message":"挂载成功","挂载数":3}`
- 规则：原子更新度量字典；**关联指标必须已存在**（不存在返回 409 并列出缺失指标）；重复挂载幂等；错误：404（数据集不存在）。

#### 5.3.7 `GET /api/schema/table/<table>` 单表 Schema

- 出参：`{"status":"ok","table":"wedw_dws.settle_surplus_area_payment_stat_df","fields":[{"字段名称":"contract_count","注释":"签约人数","字段类型":"bigint","指标":"contract_count"}]}`
- 性能：< 100ms（NFR-02）；错误：404（表不存在）。

#### 5.3.8 `GET /api/schema` 挂载表列表（分页）

- 入参（Query）：`table_prefix=wedw_dws.settle&page=1&pageSize=20`
- 出参：`{"status":"ok","items":[{"表名":"...","字段数":32,"已挂指标数":28}],"total":100000,"page":1,"pageSize":20}`
- 性能：10 万表分页 < 500ms（NFR-03）；`table_prefix` 为空返回全量分页。

#### 5.3.9 `POST /api/datasources/tables` 库表浏览（生产增强）

- 入参：在 5.2.9 基础上增加 `{"keyword":"settle_surplus","page":1,"pageSize":20}`
- 出参：`{"status":"ok","tables":[...],"total":1234,"page":1,"pageSize":20}`（keyword 为表名模糊匹配，区分大小写不敏感）
- 性能：10 万表模糊查询 < 500ms（NFR-03）。

#### 5.3.10 `GET /api/metrics` 指标列表（过滤+分页）

- 入参（Query）：`type=derived&status=已发布&数据域编号=DOM-006&术语标签=门诊慢性病&业务负责人=张三&产品负责人=李四&技术口径负责人=王五&page=1&pageSize=20`
- 出参：`{"status":"ok","items":[{"type":"派生","序列号":"148","英文名称":"tnb_manage_cnt","中文名称":"糖尿病规范管理人数","状态":"已发布","数据域":"结算费用域","术语标签":"门诊慢性病"}],"total":168,"page":1,"pageSize":20}`
- 过滤规则：`术语标签` 逗号拆分精确匹配；负责人为精确匹配；筛选条件组合 AND；性能：列表筛选 < 300ms（NFR-07）。

## 6. 智能体集成（skill）

### 6.1 metric-mapping（需求指标映射）

- 输入：需求方 Excel（指标命名+口径定义）或指标清单
- 流程：解析 → 批量检索候选 → 口径比对判定（已存在/相似/需新建）→ 输出映射报告 → 需新建时调 `/api/metrics/draft` 生成草稿
- 依赖接口：`/api/semantic/metrics`、`/api/metrics/<type>/<id>`、`/api/metrics/validate`、`/api/metrics/draft`、`/api/semantic/datasets`、`/api/semantic/lineage`

### 6.2 metric-creator（指标录入）

- 输入：数仓任务代码（Hive SQL/DDL）或需求文档
- 流程：解析候选指标 → 批量查重 → 词根校验 → 分层判定（原子/派生/复合）→ 输出草稿清单 → **先注册指标 → 再注册/挂载数据集**
- 依赖接口（含生产必补）：`/api/metrics/batch-validate`、`/api/glossary/validate-names`、`/api/metrics/batch-draft`、`/api/glossary/draft`、`/api/datasets/register`、`/api/datasets/<name>/mount`、`/api/schema/table/<table>`
- 线上模式约束：**仅 API，无本地 YAML 访问**；接口不可用时停止并报告，不静默降级

### 6.3 接口契约稳定性要求

- 智能体依赖的接口字段命名保持中文键不变（如 `英文名称`、`业务口径`）；
- 接口变更需向后兼容或走版本号；
- 批量接口限流与超时策略服务端统一控制（默认 10s）。
- 批量接口错误语义：`batch-*` 逐条返回 `ok:false + message`，整体 HTTP 200；入参校验失败（缺字段/超 100 条）返回 HTTP 400；
- 新增字段只增不改：已有中文键不得改名或改变类型；skill 侧对未知字段忽略不报错。

## 附录 B：指标英文名称命名规范

- 字符集：`^[a-z][a-z0-9_]{2,63}$`，禁止大写/连字符/空格/中文/特殊字符；
- 结构：词根组合 + 度量词后缀（`_amt`/`_cnt`/`_qty`/`_days`/`_rate`/`_ratio`）；
- 派生 = 业务限定前缀 + 依赖英文名；复合 = 公式语义命名（比率/占比）；
- 去表化：禁止物理表前缀/表名成分（`his`/`dw*`/`zkxt` 等）；**结算口径金额除外**，统一 `_settle_amt` 后缀（如 `clinic_settle_amt`），`settle` 作为"结算口径"已注册词根保留使用；
- 词根缺失：录入时提示用户确认新建，走"申请→评审→注册"。
